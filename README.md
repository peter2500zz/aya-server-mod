# aya-server-mod

一个纯服务端的 Fabric 工具性指令模组，为 Minecraft 服务器提供若干实用命令。

## 环境

| 项目 | 版本 |
|------|------|
| Minecraft | 26.3（Mojang 官方映射） |
| Fabric Loader | 0.19.5 |
| Fabric API | 0.161.0+26.3 |
| Java | 25 |

模组功能逻辑全部作用于服务端，但 `environment` 设为 `"*"`，因此在单人、局域网（集成服务器）以及专用服务器中均可正常加载。

### 本地化

命令提示文本使用本模组自己的翻译键，并采用**服务端查表 + fallback** 的方式下发：
服务端按接收方玩家上报的客户端语言，从内置语言表中查出文本，作为 fallback 与翻译键一并发送。

| 客户端情况 | 显示结果 |
|-----------|---------|
| **未安装本模组** | 显示 fallback 文本，且已按该玩家的客户端语言选好 —— 显示正确、语言匹配 |
| 安装了本模组或同名资源包 | 用客户端自己的翻译渲染，可通过资源包自定义文案 |

内置 `zh_cn` 与 `en_us` 两种语言，文件位于 `src/main/resources/assets/aya-server-mod/lang/`。

- **`zh_cn` 是基准语言**（文案母本）：新增或改写文案先改中文，再据此翻译其余语言。
- **`en_us` 是兜底语言**：客户端语言未收录时（如日语）回退到英文。

启动时会以基准语言为准校验其余语言的键集，缺键或多键都记 WARN。

## 指令列表

| 指令 | 参数 | 执行者 | 说明 |
|------|------|--------|------|
| `/here` | 无 | 仅玩家 | 对自身施加 30 秒发光效果（信标风格边框，无 HUD 图标），便于队友定位。玩家自身看不到发光轮廓，故附带一条确认提示。 |
| `/tpa <玩家>` | 目标玩家 | 仅玩家 | 向目标玩家**发起传送请求**（不是立即传送）。目标须在 30 秒内接受，逾期请求失效；接受后**发起者**被传送至目标位置，支持跨维度。补全体验与原版 `/tell` 一致（在线玩家名 + 选择器）。 |
| `/tphere <玩家>` | 目标玩家 | 仅玩家 | 与 `/tpa` 方向相反：请对方传送到自己身边。接受后被传送的是**目标玩家**。其余（30 秒时限、回应方式、撤销）与 `/tpa` 完全一致。 |
| `/accept <玩家>` | 发起者 | 仅玩家 | 接受该玩家发给自己的传送请求。补全只列出**此刻正在等你回应的人**。 |
| `/reject <玩家> [原因]` | 发起者 + 可选原因 | 仅玩家 | 拒绝该玩家的传送请求，原因会转达给对方。补全同上。 |
| `/cancel <玩家>` | 目标玩家 | 仅玩家 | 撤销自己发给该玩家、尚未被回应的请求，并通知对方。补全只列出**自己已发出且仍待回应的目标**。 |
| `/die` | 无 | 仅玩家 | 杀死自己，效果等同于 `kill @s`。死亡界面即反馈，不额外发消息。 |
| `/hat` | 无 | 仅玩家 | 将主手物品与头部装备槽物品直接对调，无视任何条件（任意物品都能戴在头上）。 |
| `/back` | 无 | 仅玩家 | 传送回上一次死亡地点（支持跨维度）。无死亡记录、或死亡所在维度已不存在时，分别给出对应提示。 |
| `/home` | 无 | 仅玩家 | 传送回设置的重生点（床 / 重生锚，支持跨维度），复用原版复活坐标查找逻辑且不消耗重生锚充能。未设置重生点、以及床/锚被破坏或遮挡，分别给出对应提示。 |

### 传送请求流程

```
Alpha: /tpa Beta
  Alpha ← 已向 Beta 发送传送请求。
          快捷操作：[撤销]

  Beta  ← Alpha 请求传送到你身边。
          快捷操作：[接受] [拒绝]

Beta:  /accept Alpha        ← 点【接受】即填好此行
```

方括号内是可点击按钮：点击会把**已填好玩家名**的指令填入聊天栏，玩家按回车确认。未安装本模组的客户端同样可用。

其中【拒绝】按钮填入的是 `/reject Alpha `，**末尾带一个空格**——光标因此落在下一个参数位上，
原版的命令提示会自动显示出可选的「原因」，不必在文案里另行解释。

> 按钮用的是 `ClickEvent.SuggestCommand` 而非 `RunCommand`。后者会让客户端弹出「确认执行指令」窗口 ——
> 因为 Minecraft 是按「无权限来源能否解析该指令」来判定指令是否受限的，与真实权限等级无关。
> 而且只有 `SuggestCommand` 会把文本留在聊天栏，上面那个空格的技巧才成立。
> 详见 [`CLAUDE.md`](CLAUDE.md#命令编写规范)。

约束与边界：

- **只有目标明确接受才会传送。** 30 秒内未回应即失效并通知双方，不传送 ——
  因此 AFK 或没留意聊天栏的玩家不会被动地被传送到身边。
- 传送会清空已累积的下落距离，坠落途中被传送不会落地摔伤。原版 `/tp` 不做这件事。
- **请求之间互不排斥**：同一玩家可以同时收到多人的请求，也可以同时向多人发出请求，
  各自独立计时、独立失效。因此三条回应指令都必须指明对方是谁 —— 点按钮时已自动填好。
  唯一被拒绝的重复情形是向**同一**目标重复发起，此时会提示先撤销。
- **`/tpa` 与 `/tphere` 共用同一条请求记录**：请求的身份是「谁向谁发起」，方向只决定接受后由谁移动。
  因此你对某人已有一条待处理请求时，无论那条原本是哪个方向，都不能再向他发起另一条 —— 想改方向须先 `/cancel`。
  接受、拒绝、撤销三条指令则完全无需关心方向。
- **反向请求视同接受**：对方正有一条发给你的待处理请求时，你发出一条指向<b>同样结果</b>的请求，
  会被直接当作接受而立即成交，不再新建请求。例如 alice `/tpa bob` 待处理时 bob 打 `/tphere alice`
  （二者都是「alice 去 bob 那」），反之亦然。
  两条**同向**请求（如双方都 `/tpa` 对方）结果相反，不构成同意，仍各自独立存在。
- 请求超时后，**未回应的一方**会收到一个【发送请求】按钮，一键把同样的意图发回去
  （原为 `/tpa` 则填 `/tphere <对方>`，原为 `/tphere` 则填 `/tpa <对方>`）。

### Carpet 联动

若服务器装有 [Carpet](https://modrinth.com/mod/carpet)，发给其 `/player` 假人的传送请求会**当场成交**，
不必等它回应 —— 假人既不看聊天栏也不会打指令，让它干等到超时毫无意义。`/tpa` 与 `/tphere` 两个方向都适用。

这是纯运行时的软联动：只按 mod id 与类名探测，**不引入对 Carpet 的编译期依赖，也不使用 Mixin**。
没装 Carpet 时完全无感，本模组照常工作。
- 三条回应指令的玩家补全**由服务端按当前请求状态过滤**，不会列出无关的在线玩家。
- 任一方掉线，请求立即作废并通知仍在线的一方。
- 请求只存在于服务器内存中，重启即清空，**不写入存档**。

## 构建

```bash
./gradlew build
```

构建产物位于 `build/libs/`，命名格式为 `asm-<模组版本>-fabric+<MC 版本>.jar`，
例如 `asm-1.1.0-fabric+26.3.jar`。把它放进服务器的 `mods/` 目录即可（带 `-sources` 后缀的是源码包，无需部署）。

> 文件名里的版本后缀只用于区分构建产物，不会写进模组自身的版本号 ——
> `fabric.mod.json` 中始终是纯 SemVer 的 `1.1.0`。
